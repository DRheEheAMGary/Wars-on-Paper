# Wars on Paper — 游戏设计与开发计划

> 版本 v0.1 · 2026-10-19 · 状态：待确认 4 项假设后进入 M0

---

## 1. 一句话定位

**Wars on Paper** 是一款网页端实时领土争夺游戏：地图由上百个城市节点组成，每座城市拥有一块边缘随机的领土并铺满全图；玩家通过占领城市吞并其领土，在 10–20 分钟内以城市数量与领土占比决出胜负。支持单机 vs AI，以及单房间 16–32 人在线乱斗。

---

## 2. 已确认的决策

| 项目 | 决策 |
| --- | --- |
| 玩法类型 | 类 territorial.io：实时扩张、攻占城市节点 |
| 时间模型 | 服务器权威实时 tick，一局 12 分钟 |
| 领土表示 | 每座城市一块随机边缘的不规则多边形，完整铺满地图，占领即整块填色 |
| 核心系统 | 资源（金币/粮食/人口）、城市等级与建设、兵种与战斗、科技树、外交与同盟 |
| 多人规模 | 单房间 16–32 人 |
| 视觉风格 | 亮色主题、颜色鲜艳（纸面军事推演感） |
| 落地顺序 | 先单机 vs AI 跑通核心循环，再做多人 |
| 技术约束 | **免编译**：原生 ES Module + Canvas 2D + Node.js，改完刷新即生效 |

## 3. 玩法设计

### 3.1 地图生成（核心算法）

一次生成、全局共享、种子可复现：

1. **地图轮廓**：用种子噪声生成 12–20 个控制点的闭合样条，作为大陆边界（纸面底图上的不规则大陆）。
2. **城市采样**：在轮廓内做 Poisson-disk 采样，最小间距由目标城市数决定（160 城约 32px/城）。
3. **初始领土**：以地图多边形为初始区域，对每个城市点用与其它城市的垂直平分线依次裁剪（半平面裁剪式 Voronoi，O(N²)，160 城约 1.3 万次裁剪，几十毫秒，仅生成时跑一次）。
4. **随机边缘**：每条相邻两城共享的边，用「边 ID（两城 id 排序后哈希）+ 地图种子」作为随机流做 1–2 次中点位移；两座城市使用**同一条曲线**（一正一反拼接），因此曲线化后仍然**不重叠、不留缝**，并集严格等于整张地图。这是“随机边缘”与“填充完全”同时成立的关键。
5. **邻接图**：共享边的城市对写入 `neighbors`（对称），用于攻击、支援与边界绘制。
6. **地形**：每城标注平原 / 森林 / 丘陵 / 山地，影响产出与防御；河流仅作视觉，不阻断连通。
7. **出生公平**：所有出生点按最大间距优先选点；每名玩家获得 1 个首都 + 2 个相邻城市，共 3 城起手。
8. **输出**：`{ seed, width, height, outline, cities[], players[] }`，纯 JSON，可序列化、可复现、可存档。

### 3.2 核心循环（单局 12 分钟）

**占领城市 → 城市产出资源与人口 → 招募部队 / 升级城市 / 研发科技 → 攻打相邻城市 → 领土扩张 → 提高分数或消灭对手。**

- 每局 720 秒；时间结束按分数排名，或仅剩一名玩家时提前结束（淘汰制）。
- 每座城市独立的产出、人口、驻军、等级、建筑槽（2 格）。
- 进攻只能沿邻接图进行（相邻城市），形成战线与包围感。

### 3.3 城市数值（初值，`data/balance.json` 运行时热加载）

| 等级 | 金币/秒 | 粮食/秒 | 人口上限 | 驻军上限 | 城墙防御 | 升级消耗 / 耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 2.0 | 0.5 | 100 | 150 | +0% | 200 金 / 15 秒 |
| 2 | 3.0 | 1.0 | 150 | 300 | +30% | 500 金 / 30 秒 |
| 3 | 4.5 | 1.5 | 220 | 450 | +60% | 1200 金 / 45 秒 |
| 4 | 6.5 | 2.0 | 300 | 700 | +90% | 2600 金 / 60 秒 |
| 5 | 9.0 | 3.0 | 400 | 1000 | +120% | — |

- 人口增长：+1.5/秒 × (1 + 0.25 × (等级−1))，上限见上表。
- 升级期间城市正常产出，但防御不提升，直到完成。
- 占领后城市等级 −1（最低 1 级），保留 50% 幸存攻军作为驻军。
- 建筑槽（2 格）：市集（+25% 金币）/ 粮仓（+25% 粮食）/ 兵营（+30% 驻军上限）/ 城墙（+20% 防御）——M5 实现。

### 3.4 资源经济

| 资源 | 来源 | 消耗 | 规则 |
| --- | --- | --- | --- |
| 金币 | 城市每秒产出 | 招募、升级、科技 | 归零时无法招募/升级，已有军队不受影响 |
| 粮食 | 城市每秒产出 | 军队维护：0.005 粮/兵/秒 | 粮食为负时，全军每秒损失 1% 兵力（断粮惩罚） |
| 人口 | 城市人口增长 | 招募消耗 | 人口池按城市独立；招募立即扣人口、立即出兵 |

### 3.5 兵种与战斗

| 兵种 | 攻击 | 防御 | 跨城耗时 | 金币 | 人口 | 特性 |
| --- | --- | --- | --- | --- | --- | --- |
| 步兵 | 10 | 10 | 8 秒 | 20 | 5 | 对攻城车 ×1.5 |
| 骑兵 | 16 | 6 | 4 秒 | 45 | 8 | 对步兵 ×1.5，机动强 |
| 攻城车 | 8（对城 ×3） | 4 | 12 秒 | 90 | 12 | 削减城墙系数，对守军弱 |

**结算公式**（到达目标城时一次性结算，服务器种子 RNG ±10%）：

```
A = Σ(攻击方兵力 × 攻击 × 克制 × 地形攻 × 科技攻)
D = Σ(守军兵力 × 防御 × 城墙(1 + 0.3×(等级−1)) × 地形守 × 科技守)
p = A / (A + D)
攻击方损失 = round(攻击方总数 × (1−p) × 0.7)
守方损失   = round(守军总数 × p × 0.7)
```

- 守军清零 → **占领**：幸存攻军进驻，执行占领结算。
- 守军未清零 → 幸存攻军沿原路撤回出发城市（可被拦截，v1 不做拦截）。
- 无守军 → 直接占领。
- 战斗与行军由服务器统一推进；前端只做动画表现。

### 3.6 科技树（3 系 × 3 层）

| 系 | 一层 | 二层 | 三层 |
| --- | --- | --- | --- |
| 军事 | 操练：+10% 攻击 | 甲胄：+15% 防御 | 战术：行军 −20% 耗时 |
| 经济 | 税制：+20% 金币 | 仓储：+30% 粮食 | 人口：+25% 人口上限 |
| 扩张 | 筑路：连城行军 −15% | 攻城：攻城车对城 ×1.3 | 声望：占领后保留驻军 +10% |

- 消耗：200 / 500 / 1200 金；研发耗时：15 / 30 / 60 秒；全局生效，同一时间只研发一项。
- 科技是“长线成长”的少量加成，不改变核心兵种克制。

### 3.7 外交（仅多人）

- **结盟**：向目标玩家发起，30 秒内对方接受即生效，最多 2 个盟友；盟友之间不能攻击、不能抢占。
- **停战**：双方同意后 60 秒内不能互相攻击。
- **背叛**：单方解除；解除后 60 秒内不能再次结盟，且解除方 60 秒内攻击力 −10%（背信惩罚，可在配置中关闭）。
- 分数独立计算，一局只有一个赢家。

### 3.8 胜负与计分

```
分数 = 城市数 × 100 + 领土面积占比(%) × 20 + 科技数 × 50 + 累计歼敌兵力 × 0.2
```

- 12 分钟结束：分数最高者胜；若开启淘汰，仅剩一人立即结束。
- 被淘汰玩家进入观战；单机模式被淘汰即结算。

### 3.9 单机模式

- 可配置：地图种子、城市数（60 / 100 / 140）、AI 数量（1–7）、难度（简单 / 普通 / 困难）、对局时长。
- 可暂停（空格）、可 1× / 2× 加速（单人模式直接提高模拟速率，不影响规则）。
- 单机模拟运行在 Web Worker 中，UI 永不卡顿。

### 3.10 操作与信息

| 操作 | 行为 |
| --- | --- |
| 左键点击城市 | 选中，显示城市面板（等级/人口/驻军/产出/建筑） |
| 点击相邻城市 + 拖动 | 选择目标，弹出派兵面板（三兵种数量滑条） |
| 右键 | 快速派兵（按上次比例）到最近的敌对相邻城 |
| 滚轮 | 以鼠标为中心缩放 |
| 拖拽空白 / WASD | 平移地图 |
| 空格 | 单机暂停 / 多人无操作 |
| Tab | 计分板（实时排名、城市数、分数） |
| Esc | 暂停菜单 / 退出确认 |

信息展示：城市填充玩家色 + 描边；兵力数字随缩放隐藏（< 0.6 倍只显示颜色）；攻击时显示行军箭头与计时环；被攻击城市闪烁告警。

## 4. 技术方案（免编译）

### 4.1 为什么可行

- 浏览器原生支持 ES Module + `import`，所有代码**直接以源码运行**，无需打包/编译。
- 静态服务器由 Node 原生 `http` 实现（零依赖），配合 SSE 实现「保存文件 → 浏览器自动刷新」。
- 服务器端 Node 直接运行 ESM，唯一运行依赖是 `ws`（纯 JS，无编译）。
- 类型提示：`// @ts-check` + JSDoc + `jsconfig.json`，编辑器有完整补全，但不参与运行、不需要 `tsc`。
- 测试：Node 内置 `node --test`，不需要 Jest/Vitest。
- **改代码 → 刷新（或自动刷新）→ 立即生效**，没有构建等待。

### 4.2 运行方式

| 命令 | 作用 | 端口 |
| --- | --- | --- |
| `npm run dev` | 静态开发服务器 + SSE 热刷新（单机可玩） | 8080 |
| `npm run server` | 静态资源 + WebSocket 多人服务器 | 8080 |
| `npm test` | 运行全部单元测试（`node --test`） | — |
| `node tools/bench.js` | 模拟性能基准 | — |

浏览器访问 `http://localhost:8080`；单机模式不依赖后端逻辑，打包后的静态文件可直接部署到任意静态托管。

### 4.4 共享模拟引擎

- **纯函数、无 DOM、无网络**：`sim.js` 接收状态与指令数组，返回新状态与事件列表。
- **固定步长**：10 Hz（每 tick 100ms），服务器按真实时间累积推进；单机 Worker 同样按此频率。
- **确定性**：所有随机数来自种子 RNG；同种子 + 同指令序列 → 完全相同结果（便于回放与测试）。
- **可序列化**：状态是纯 JSON，可直接快照/存档/传输。
- **单机与多人同一套规则**：AI 也使用同一指令接口，不存在“另一套简化规则”。

### 4.5 网络同步

- 服务器权威：客户端只发送指令，不修改状态。
- 指令：`deploy`（派兵到相邻城）、`recruit`（招募）、`upgrade`（升级）、`research`、`diplomacy`、`setName`。
- 校验：城市归属、邻接关系、资源/人口、冷却（攻击 2 秒/城）、同 tick 指令去重、限频（20 条/秒/玩家）。
- 同步频率：模拟 10 Hz，**增量快照 5 Hz**；加入/重连时下发全量快照。
- 增量策略：只发变化字段；行军只发一次「出发 tick / 到达 tick / 兵力」，客户端自行插值移动 → 流量极小。
- 客户端不预测：策略游戏 100–200ms 指令延迟可接受，第一时间播放本地反馈动画。
- 流量预算（32 人 / 160 城）：典型 1–5 KB/快照，服务器上行约 0.6 MB/s；若紧张可降到 2 Hz 或启用二进制编码（v1.1）。

### 4.6 房间与匹配（v1：单房间循环）

```
LOBBY(45s) → MATCH(12min) → RESULT(20s) → LOBBY ...
```

- 大厅显示在线玩家、准备状态、倒计时；≥2 人可开始（可配置最少人数）。
- 单房间上限 32 人，超出拒绝并提示。
- 开局：服务器生成种子 → 广播 `start`（含地图种子、规则配置、玩家列表）→ 各客户端用**同一 mapgen 代码**各自生成完全一致的地图（只传种子，不传 160 个多边形，省流量）。
- **断线重连**：60 秒宽限；客户端凭本地 token 恢复；期间城市照常产出但不会行动。
- **中途加入**：默认观战，下一局加入；可配置 `midMatchJoin` 允许“空降”（1.5× 起始资源、出生在无主区域），默认关闭。
- 淘汰玩家自动转为观战。

### 4.7 性能预算

| 指标 | 目标 |
| --- | --- |
| 服务器 tick（160 城 / 500 行军 / 32 玩家） | p95 < 2ms |
| 单客户端下行流量 | 典型 < 10 KB/s |
| 前端帧率（1440p） | 60 fps |
| 首屏 JS（无框架、无依赖） | < 300 KB |
| 内存（浏览器标签页） | < 200 MB |

渲染优化：静态地图（地形 + 城市多边形底）绘制到离屏 Canvas 一次；归属色层仅在所有权变化时重绘；行军与特效在主循环重绘。

### 4.8 安全与公平

- 服务器权威，客户端无法伪造资源/兵力/归属。
- 所有指令必须通过校验：归属、邻接、资源、冷却、上限。
- 地图种子由服务器生成；同局所有玩家使用同一地图。
- 客户端只接收公开信息（不做战争迷雾，territorial 风格全公开）。

### 4.9 部署与存储

- 单个 Node 进程同时提供静态文件与 WebSocket（同源，无 CORS）。
- 可直接部署到 Fly.io / Render / 任意 VPS；无构建产物，`git pull && npm i ws && npm run server` 即上线。
- v1 无数据库：对局状态在内存中；可选将每局结果写入 `data/results.json` 做简易排行榜。
- 后续（v2）再引入 SQLite/Postgres、多房间、匹配分与账号。

## 5. 数据模型与协议

### 5.1 核心状态（简化 JSDoc 描述）

```js
// MatchState
{
  seed, tick, phase: 'lobby'|'match'|'result',
  config: { durationSec, mapSize, maxPlayers },
  players: [{
    id, name, color, alive,
    gold, food, pop,            // 全局资源池（城市也各有产出）
    techs: { military: 0|1|2|3, economy: ..., expansion: ... },
    researching: { techId, endsAtTick } | null,
    allies: [playerId], truce: [{ id, untilTick }],
    score, kills
  }],
  cities: [{
    id, name, polygon: [[x,y],...], centroid: [x,y],
    neighbors: [cityId], terrain,
    ownerId: playerId|null,
    level, population, garrison: { inf, cav, siege },
    buildings: [id], upgrading: { endsAtTick, toLevel } | null
  }],
  armies: [{
    id, ownerId, fromCity, toCity,
    units: { inf, cav, siege },
    departTick, arriveTick
  }],
  events: []                      // 本 tick 事件（占领/战斗/断粮），用于前端特效与日志
}
```

### 5.2 指令（客户端 → 服务器）

| type | 字段 | 说明 |
| --- | --- | --- |

## 6. AI 设计

- **同规则**：AI 只通过 `commands.js` 的指令接口行动，不做资源作弊（难度系数仅作平衡参数）。
- **决策周期**：简单 1500ms / 普通 800ms / 困难 500ms。
- **思路**：Utility AI —— 每个决策周期评估所有可行动作的期望收益：
  - 进攻：目标城市价值（等级/产出/位置）+ 守军差 − 行军风险；
  - 升级：金币回本时间；
  - 科技：边际收益 / 当前局势；
  - 防御：对邻接敌军的兵力缺口。
- **阶段**：早期（0–3 分钟）抢中立城；中期（3–8 分钟）发展经济、争夺邻接；后期（8 分钟后）集火弱敌、固守首都。
- **难度参数**：资源系数（0.9 / 1.0 / 1.1）、决策噪声、是否集火、是否撤退、反应延迟。
- **可测试**：无头跑 AI vs AI 100 局，统计胜率、平均城市数、平均局时，用于平衡。

## 7. 前端与视觉

### 7.1 页面流程

### 7.2 渲染分层（Canvas 2D）

| 层 | 内容 | 重绘时机 |
| --- | --- | --- |
| 底图 | 纸面纹理、地图轮廓、河流 | 地图生成时一次 |
| 地形层 | 地形色块/纹理、城市多边形底 | 静态，缓存 |
| 归属层 | 玩家色填充、边界描边、前线高亮 | 所有权变化时 |

| 信息层 | 城市名、兵力数字、选中高亮、攻击告警 | 每帧（按缩放级别） |
| DOM HUD | 资源条、计时器、计分板、城市面板、按钮 | 状态变化时 |

### 7.3 视觉规范（亮色鲜艳）

- 背景：纸面米白 `#F6F0E2`，地图外浅灰蓝。
- 地图轮廓：深灰描边 `#3A3A3A`，内部城市边界细线。
- 玩家色板：HSL 黄金角生成 32 色（S≈68%，L≈52%），保证亮底上可读；相邻出生点颜色索引错开。
- UI：白底卡片 + 强对比深色文字 + 玩家色点缀，圆角、轻阴影。
- 动效：占领波纹 300ms、行军箭头随进度推进、被攻击城市红色脉冲；全部 CSS/Canvas 实现，无外部素材依赖。
- 字体：系统字体栈（中文优先），城市名使用小号衬线体增强“纸面推演”感。

### 7.4 输入与适配

- 桌面优先：最小 1024×640，推荐 1440p；HUD 自适应。

## 8. 里程碑与验收

> 估算按「我为主开发、AI 辅助」计算，1 人日 ≈ 6 小时有效开发。

### M0 工程骨架（0.5 人日）

- 交付：目录结构、`package.json`、`jsconfig.json`、零依赖 `dev.js`（静态 + SSE 热刷新）、`index.html` 主菜单空壳、`constants.js`、README 更新。
- 验收：`npm run dev` 打开 8080；修改任意源码 → 浏览器自动刷新；`npm test` 通过。

### M1 地图与渲染（1 人日）

- 交付：`mapgen.js` 全流程、`tools/mapdebug.html` 可视化、Canvas 渲染 + 相机（拖拽/滚轮缩放/边界钳制）、城市名与邻接关系。
- 验收：同种子逐像素可复现；多边形并集无缝隙、无重叠；邻接对称；拖动缩放 60fps；调试页可看到城市多边形与邻接边。

### M2 单机核心循环（1.5 人日）

- 交付：经济 tick、招募、升级、行军、战斗结算、占领、计分、HUD、选城派兵交互、Web Worker 单机模拟、暂停/2×。
- 验收：可占领中立城并持续扩张；资源/人口/粮食按数值表变化；占领后颜色立即更新；一局能正常结束并显示结算。

### M3 AI 与单机完整（1 人日）★ 首个可玩版本

- 交付：AI 决策器、3 档难度、单机设置页（种子/城市数/AI 数量/难度/时长）、结算页、玩法说明。
- 验收：普通 AI 会扩张与进攻；困难明显强于简单；1v1 到 1v7 均能跑完不崩溃；无卡死/发呆 AI；单机全流程无需联网。

### M4 多人联网（2 人日）★ 多人可玩

- 交付：WebSocket 服务器、单房间循环、大厅、全量/增量快照、指令校验、断线重连、观战、结算同步。
- 验收：本地双浏览器对战；`tools/bench` 用 16 个无头客户端跑完整局无状态漂移；断网 30 秒重连后状态一致；32 人模拟压测 tick p95 < 2ms。

### M5 系统扩展（2 人日）

- 交付：科技树、外交（结盟/停战/背叛）、建筑槽、兵种平衡、排行榜（可选）。
- 验收：科技研发并生效；结盟后无法互攻；全部系统均有 UI 入口；AI 会使用科技与外交。

### M6 打磨与上线（1.5 人日）

- 交付：亮色视觉与动效、性能优化、部署脚本与文档、玩法说明页。
- 验收：1440p 60fps；32 人局稳定运行；公网可访问；README 完整（启动/玩法/部署）。

**总计约 9.5 人日**；M3 末（约 4 人日）单机可玩，M4 末（约 6 人日）多人可玩。

## 9. 测试与质量

- 运行：`node --test tests/`（Node 内置，无需安装测试框架）。
- **mapgen**：面积覆盖 ≈ 地图面积（±0.1%）、两两交集面积 ≈ 0、邻接对称、同种子复现、不同种子有效。
- **combat**：0 守军直接占领、0 攻方无效、克制关系生效、损失不超过总兵力、占领后等级/驻军正确。
- **economy**：资源永不为负、上限截断、断粮惩罚生效、人口增长符合公式。
- **commands**：非邻接/非本人城市/资源不足/冷却中/超频的指令被拒绝且不改变状态。
- **snapshot**：delta 连续应用后与全量快照逐字段一致；1000 tick 随机指令 fuzz 不崩溃、不出现负资源。
- **AI 回归**：AI vs AI 100 局，胜率与局时分布作为平衡基线。
- 每个里程碑结束执行一次手动验收清单（见各里程碑「验收」）。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 平衡性（数值、兵种、AI 强弱） | 可玩性 | 数值全部放 `data/balance.json` 运行时热调；AI vs AI 批量统计；每轮迭代微调 |
| 32 人同步流量与延迟 | 多人体验 | 稀疏增量 + 5Hz + 行军一次下发；预留二进制编码；必要时降频 |
| 免编译方案随规模变得难维护 | 开发效率 | 严格 shared/client/server 三层边界；shared 纯函数；JSDoc 类型；如规模超预期可平滑引入打包器（代码本身已是标准 ESM） |
| 自研 Voronoi/抖动出缝隙或自交 | 地图错误 | 单元测试断言面积与交集；`mapdebug.html` 可视化；固定抖动幅度上限（≤ 边长 15%） |
| 浏览器差异 | 兼容 | 只用标准 Canvas/DOM API，不依赖实验特性；Safari/Chrome/Firefox 手动回归 |
| 单人后期卡顿 | 帧率 | 模拟放 Web Worker；静态层离屏缓存；归属层按变化重绘 |
| 中途加入玩家体验差 | 多人留存 | 默认观战+下局加入；可选空降补偿；显示观战数据 |
| 范围蔓延 | 工期 | v1 明确不做清单；M3 单机版先上线收集反馈 |
